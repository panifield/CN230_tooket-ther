## รายละเอียดงานและเกณฑ์คะแนน

### 1. การวิเคราะห์ระบบ (10%)

ในส่วนนี้ให้อธิบายว่าระบบที่เลือกมีปัญหาอะไร ต้องการแก้ปัญหาอะไร และใครเป็นผู้เกี่ยวข้องกับระบบ

- อธิบายภาพรวมของระบบ เป้าหมาย และขอบเขตงาน
- ระบุผู้มีส่วนได้ส่วนเสีย (Stakeholders) พร้อมบทบาทของแต่ละฝ่าย
- ระบุ Use Case หลักของระบบ โดยควรมีอย่างน้อย 1–2 กรณีตัวอย่างที่อธิบายได้ชัดเจน
- ระบุ Functional Requirements เป็นข้อความที่ชัดเจนและตรวจสอบได้ ควรมีประมาณ 5 ข้อขึ้นไป

**ตัวอย่างการเขียนสำหรับระบบจองโรงแรม:**

**Stakeholders:**
- ลูกค้า: ค้นหาห้องพัก ดูราคา ทำการจอง และยกเลิกการจอง
- พนักงานต้อนรับ: ตรวจสอบข้อมูลการจอง ยืนยันการเข้าพัก และบันทึกการเช็กอิน/เช็กเอาต์
- ผู้จัดการโรงแรม: ตรวจสอบรายงานการเข้าพัก รายได้ และสถานะห้องพัก
- ผู้ดูแลระบบ: จัดการข้อมูลห้องพัก ประเภทห้อง ราคา และบัญชีผู้ใช้งาน

**Use Case:**
- ชื่อ Use Case: จองห้องพัก
- ผู้ใช้งานหลัก: ลูกค้า
- เงื่อนไขก่อนเริ่ม: ลูกค้าเลือกวันเข้าพัก วันออก และประเภทห้องพักแล้ว
- เหตุการณ์หลัก: ระบบค้นหาห้องว่าง ลูกค้าเลือกห้อง กรอกข้อมูลการจอง และระบบบันทึกการจอง
- ผลลัพธ์: ระบบออกเลขที่การจองและอัปเดตสถานะห้องพัก

**Functional Requirements:**
- ระบบต้องสามารถค้นหาห้องพักว่างตามช่วงวันที่ลูกค้าเลือกได้
- ระบบต้องสามารถบันทึกข้อมูลการจองห้องพักของลูกค้าได้
- ระบบต้องสามารถคำนวณราคาค่าห้องพักรวมตามจำนวนคืนได้
- ระบบต้องสามารถยกเลิกการจองและปรับสถานะห้องพักกลับเป็นว่างได้
- ระบบต้องสามารถแสดงรายการการจองของลูกค้าแต่ละรายได้

---

### 2. การออกแบบฐานข้อมูล (25%)

ในส่วนนี้ให้ออกแบบโครงสร้างฐานข้อมูลให้สอดคล้องกับความต้องการของระบบ

- ออกแบบ E/R Diagram หรือ UML Class Diagram โดยระบุ entity/class, attribute และความสัมพันธ์ระหว่างข้อมูล
- ระบุ cardinality ของความสัมพันธ์ที่สำคัญให้ชัดเจน
- แปลงแบบออกแบบเป็น Relational Schema พร้อมกำหนด Primary Key และ Foreign Key
- อธิบายการทำ Normalization ตามความเหมาะสม
- หากมีข้อสมมติในการออกแบบ ควรระบุไว้ให้ชัดเจน

---

### 3. การพัฒนาฐานข้อมูล (25%)

ในส่วนนี้ให้นำแบบออกแบบมาสร้างเป็นฐานข้อมูลจริง

- เขียนคำสั่ง SQL สำหรับสร้างตาราง (DDL)
- เพิ่มข้อมูลตัวอย่าง (DML) ให้เพียงพอสำหรับการทดสอบระบบ
- กำหนด Constraints ที่จำเป็น เช่น PK, FK, UNIQUE, CHECK และ NOT NULL
- สามารถเพิ่ม Index, View หรือองค์ประกอบอื่นได้ตามความเหมาะสม
- ควรจัดไฟล์ SQL ให้เป็นระเบียบและสามารถนำไปรันซ้ำได้

---

### 4. Query และตรรกะทางธุรกิจ (20%)

ในส่วนนี้ให้นำฐานข้อมูลมาใช้ตอบคำถามหรือสนับสนุนการทำงานของระบบ

- เขียนคำสั่ง Query ที่สอดคล้องกับการใช้งานจริงของระบบ
- ควรมี Query อย่างน้อย 5 คำสั่งที่แสดงความสามารถของฐานข้อมูล
- ใช้คำสั่ง SELECT ขั้นสูง เช่น JOIN, GROUP BY, HAVING, Subquery หรือ View ตามความเหมาะสม
- อธิบายสั้น ๆ ว่าแต่ละ Query ใช้ตอบคำถามอะไรหรือสนับสนุนการทำงานส่วนใด

---

### 5. การพัฒนา Interface (10%)

ในส่วนนี้ให้นำระบบฐานข้อมูลไปเชื่อมต่อกับโปรแกรมที่ผู้ใช้สามารถใช้งานได้จริง

- พัฒนา Web หรือ Application ที่เชื่อมต่อกับฐานข้อมูล
- รองรับการทำงานแบบ CRUD (Create, Read, Update, Delete) สำหรับข้อมูลหลักของระบบ
- ควรมีหน้าจอหรือฟังก์ชันสำหรับเพิ่มข้อมูล ค้นหา/แสดงผล แก้ไข และลบข้อมูล
- หากใช้ AI ช่วยสร้าง Interface หรือโค้ด ต้องสามารถอธิบายโครงสร้างโปรแกรม การเชื่อมต่อฐานข้อมูล และการทำงานของโค้ดได้

---

### 6. รายงานและการนำเสนอ (10%)

ในส่วนนี้ให้นำเสนอผลการทำงานของกลุ่มอย่างครบถ้วน

- จัดทำรายงานฉบับสมบูรณ์ (PDF)

- สาธิตการทำงานของระบบ (Demo) ให้เห็นการเชื่อมต่อกับฐานข้อมูลจริง
- นำเสนอผลงานหน้าชั้นเรียน ประมาณ 10–15 นาทีต่อกลุ่ม
